# 验证范围与使用边界

回归测试使用独立临时目录、SQLite 副本、隔离 MariaDB 和打包进程。部署一致性检查用于确认安装正确；回归测试用于验证受支持的行为；实际迁移的覆盖范围则由当次 dry-run 报告确认。这三类检查不能相互替代。

| 风险或行为 | 验证方式 |
| --- | --- |
| 用户名大小写、离线 UUID、旧正版绑定 | 规范名、UUID 形态、AuthMe 绑定和密码保留回归 |
| 自动发现遗漏 | YAML/JSON/TOML/Properties、启用状态、卸载插件、自定义表前缀 |
| manifest 过期 | 每次重新发现、范围变化重扫、SQL 身份范围事务内复核 |
| PlayerPoints 积分覆盖 | 双方余额累加、整数上限、事务中途失败、重放及完整回退 |
| PlayerParticles 效果丢失 | 保留对象 UUID 与组引用、同名组另存、逻辑孤立引用检查 |
| Plan 父子引用 | 修改身份时保持内部主键及子表关联；未适配的父记录合并拒绝执行 |
| 皮肤、世界和加密数据误改 | 区分玩家所有者与皮肤来源、世界 UUID、Lore 等保留语义 |
| NBT、region 与外部区块 | 多种 UUID 编码、区块依赖摘要、可复用检查点和残留校验 |
| 强制中断、取消和恢复 | 独立节点进程、持久意图、跨节点屏障和故障注入 |
| 地图权限受迁移 umask 影响 | 游戏文件 0644、目录 0755，迁移状态保持私有 |
| 部署中断和版本混用 | 多节点一致性、原子替换、故障回滚和手工修改保护 |

## 执行验证

```bash
./hammermigrate verify
```

默认运行物理、SQLite 和打包回归。需要 MariaDB 时，将专用临时实例的 UNIX socket 传入；测试创建随机临时库并在结束后删除。

```bash
HAMMERMIGRATE_TEST_MYSQL_SOCKET=/path/to/disposable-test.sock ./hammermigrate verify
```

运行实际服务器进程的冒烟验证工具位于 `tests/platform_smoke.py`，使用独立服务目录和端口。测试数据库必须与生产隔离。

## 能保证什么

在配置范围、已支持格式和字段语义内，扫描结果通过后可以生成并执行可回退的迁移计划。未知字段和未支持的冲突保持阻塞，预检失败允许游戏继续启动而不会标记迁移成功。发生实际写入后，未完成恢复仍会阻止启动。

“自动发现”不能替代外部数据源清单。未挂载的目录、其他主机的数据库、未配置的库名范围、未知压缩格式、签名或加密内容，以及忽略项，都不能据此声明已全部迁移。对这些内容需要显式配置、字段规则或专用适配器。

`ready=true` 配合 `completion=complete` 才表示当前发现范围内的完整通过。`with-exclusions` 表示按配置跳过了部分异常，必须单独审阅。正式操作前关闭参与者和其他数据库写入方，并审阅当次 manifest。

## 使用数据副本验证

插件版本、表结构或存储方式与回归样例不同时，可在隔离环境中使用数据副本验证：

1. 复制需要验证的文件和数据库表结构、数据，使用独立连接配置，确保测试进程无法写入正式环境。
2. 分别执行普通改名和显式 `--merge`，检查身份引用、余额、对象关联与冲突处理。
3. 执行回退，将数据库行、文件内容和路径与迁移前的副本逐项核对。
4. 记录验证使用的插件版本、扫描范围、排除项和结果，避免把样本验证视为全部数据已通过。

仅复制数据库不能验证世界目录、NBT、region、外部区块和物理路径。格式回归也不能代替实际目录的扫描；正式迁移仍应审阅当次 manifest。
